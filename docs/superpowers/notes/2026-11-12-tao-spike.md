# Tao mirror-window spike (Task 0): results

Date: 2026-11-12. Spike code: branch `spike/tao-mirror` (commit `a2c7290`; throwaway, never pushed or merged).
Device: NUU S6003L (Android 12, 720x1560), USB. Host: macOS, Retina main display (scale 2) plus an external
display (scale 1). Nucleus 2.5.18 (`nucleus-application`, `decorated-window-tao`, `decorated-window-material3`) on
JBR 25, same jvmArgs as `nucleus.application`.

## Verdict: PENDING-USER

The spike builds, launches as a Tao window and shows live video. The GO rule needs draws/s and the aspect lock
measured **during a real macOS live-resize drag**. That could not be measured automatically: posting CGEvents needs
Accessibility permission (`AXIsProcessTrusted=false`), so the posted mouse drag and key press were dropped. The
numbers below come from idle and from a programmatic resize proxy, which does not run AppKit's live-resize loop and
ignores `contentAspectRatio`. The user must do the drag test (see "How the user runs it").

## What the spike does

`composeApp/src/jvmMain/kotlin/com/programmersbox/scrcpyviewer/spike/TaoSpike.kt`, run by `:composeApp:runTaoSpike`:

- `startAppKoin()`, then `MirrorController.open(SPIKE_SERIAL)`, then `nucleusApplication(enableSingleInstance = false)`
  with one `MaterialDecoratedWindow` + `MaterialTitleBar`.
- Draws `session.frames` letterboxed in a Compose `Canvas` (`frame.use { Image.makeFromBitmap(it) }` and
  `nativeCanvas.drawImageRect`).
- Overlay: draws/s over the last 1 s and `session.fps`; a button (or the D key) opens a Material3 `AlertDialog`.
- macOS: `setContentAspectRatio:` on `taoWindow.getNsWindowHandle()` with ratio `W : (W * fh / fw + titleBar)` in
  points, W = the current content width. The window is also sized to that ratio once, because the ratio only
  constrains user resizes.
- stdout, prefix `SPIKE`: one `SEC` line per second (phase, draws/s, new frames drawn/s, session fps, onResized
  events/s, canvas size, worst aspect error, widest letterbox bar); every `onPreviewKeyEvent` / `onKeyEvent` with
  `nativeKeyEvent` class and AWT id; every 10th `onResized` with `outerBoundsPx`, scale and canvas px; drag release
  bounds; `ASPECT` per drawn frame during drags.
- `SPIKE_AUTODRAG=1`: moves the window to (200, 120) on the main display, 5 s idle, then CGEvent drags of the
  bottom-right corner (4 s), right edge (3 s) and bottom edge (3 s), a click plus an `a` key press, then the dialog.
  Without Accessibility trust it runs a programmatic `setInnerSize` proxy (60 Hz, ±35 %, 10 s) instead.
  `SPIKE_AUTOEXIT=1` quits when done.

## Measured results

Phone content kept moving with an `adb shell input swipe` loop, because scrcpy sends no frames for a still screen.

Run 2 (window on the Retina display, phone animating):

| Phase | draws/s (per second) | new frames drawn/s | session fps | onResized/s |
|---|---|---|---|---|
| Idle (3 s steady) | 41, 44, 47 (mean 44.0) | 40, 43, 46 (mean 43.0) | 40.9, 44.0, 44.0 | 0 |
| Programmatic resize proxy (10 s) | 48, 64, 60, 73, 63, 65, 76, 80, 83, 56 (mean 66.8) | 42, 37, 37, 40, 36, 39, 44, 47, 45, 31 (mean 39.8) | 40.0 to 47.1 (mean 43.3) | 25, 84, 106, 95, 93, 88, 97, 98, 95, 88 |
| Idle after | 38, 43 | 37, 42 | 44.0, 40.1 | 0 |

- During the proxy resize, draws/s was 152 % of idle and distinct video frames drawn per second were 93 % of idle
  (39.8 / 43.0). The session fps did not drop. Proxy only: this is not the live-resize loop.
- Run 3 (phone still): proxy resize gave 38 to 45 draws/s for about 92 `onResized` events/s, so Compose drew about
  once per two resize events.
- Aspect: after the one-time fit, idle canvas 840x1820 px had 0.00 % aspect error and no bar (before the fit,
  840x1720 px had 5.81 % error and a 23 px bar). The proxy resize does not honour `contentAspectRatio`, so its 8.73 %
  error and 24 px bars say nothing about (b).
- Predicted from the ratio math: a fixed 40 pt title bar folded into one ratio is exact only at the width it was set
  for (420 pt here). At 274 pt width the video would get about 3 pt side bars; at 500 pt about 4 pt top and bottom bars.
  Expect a thin strip (c) away from the start width unless the ratio is re-set after each resize, or resizing is
  constrained another way (for example `windowWillResize:toSize:`).
- Screenshots (scratchpad of the spike session) showed live phone video in the Tao window, with the overlay.

## Results (a) to (g)

- **(a) draws/s and session fps, drag vs idle.** Idle: 44.0 draws/s, session 43 fps. Real drag: **not measured**
  (no Accessibility). Proxy resize: 66.8 draws/s, 39.8 new frames/s, session 43.3 fps. **User to measure.**
- **(b) aspect holds during the drag, no snap on release.** **Not measured** (the proxy ignores the ratio).
  `setContentAspectRatio:` was applied without error and the initial fit is exact. **User to judge.**
- **(c) edge strip.** **Not measured during a drag.** Predicted few-point strips away from the start width (above).
  **User to judge.**
- **(d) lag, stretch, flicker, stutter vs Claude Manager.** **User to judge.**
- **(e) Material3 `AlertDialog` under Tao.** **Yes.** It composed, laid out (text at (182, 856) px, 250x40 px) and
  showed in the screenshot over the live video.
- **(f) `onPreviewKeyEvent` carries `java.awt.event.KeyEvent`, KEY_TYPED too.** **Not measured** (the posted key was
  dropped without Accessibility). The spike logs it: press keys in the window and read the `KEY` lines
  (`isAwtKeyEvent`, `awtId` 400 = TYPED, 401 = PRESSED, 402 = RELEASED). **User to run.**
- **(g) units.** Measured on the Retina display (scale 2.0), window 420x900 pt:
  - `onResized(w, h)`: **physical pixels**, the full outer size with the title bar: `onResized(958, 2168)` with
    `outerBoundsPx` 958x2168 and `boundsOnScreen()` 479x1084 pt at scale 2.
  - `outerBoundsPx()`: **physical pixels**, position included: `[400, 240, 840, 1800]` after `setOuterPosition(200, 120)`.
  - `NucleusWindow.boundsOnScreen()`: points (`outerBoundsPx / scaleFactor`): `(200, 120, 420, 900)`.
  - `setInnerSize` and `setOuterPosition`: points.
  - Compose canvas size: physical pixels (840x1720 for 420x860 pt of content). Title bar: 40 pt (80 px at scale 2).
  - On the scale-1 display all of these are equal, so test units on a Retina display.
  - `onResized` runs on a non-AppKit thread (`Thread-11`), and its arguments can lag `outerBoundsPx()` read in the
    same callback (for example `onResized(728, 1560)` while `outerBoundsPx` was 690x1478), so treat them as queued
    events.

## Other observations

- With no position set, Tao opened the window on the external display (x = -1170).
- `setInnerSize` was clamped to the screen height (958x2168 px max) and moved the window to y = 33 pt.
- One screenshot showed a dark rectangle next to the window after the proxy resize; it was not identified (it may be
  another app's window). Worth watching for during the manual test.

## How the user runs it

From `/Users/jacobrein/Desktop/scrcpy_viewer/.claude/worktrees/resize-performance`:

```bash
cdm acquire --category phone --android --real
git switch spike/tao-mirror
# Interactive: drag every edge and corner fast for 10 s; press D (or the button) for the dialog; type some keys.
SPIKE_SERIAL=<serial from cdm acquire> ./gradlew :composeApp:runTaoSpike | grep SPIKE
# Optional automatic drag: first give your terminal app Accessibility permission
# (System Settings > Privacy & Security > Accessibility), then:
SPIKE_SERIAL=<serial> SPIKE_AUTODRAG=1 SPIKE_AUTOEXIT=1 ./gradlew :composeApp:runTaoSpike | grep SPIKE
git switch worktree-resize-performance
cdm release --android
```

Keep the phone screen moving (scroll a list, or play a video) so the session sends frames. Compare draws/s in the
`SEC phase=drag-*` lines (or the overlay during a manual drag) with the idle lines. GO needs draws/s during the drag at
least 80 % of idle, and the aspect holding (no letterbox strip growing during the drag, no snap on release). Then run
Claude Manager next to it and compare lag, stretch, flicker and stutter.
